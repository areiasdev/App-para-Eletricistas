# Full review — architecture, code quality, and fit for electricians & builders (Sep 2026)

Scope: the whole repo (ASP.NET Core 10 API in Clean Architecture, Next.js 16 frontend, Docker
deploy). I compared it against how Portuguese electricians, maintenance technicians and small
construction companies actually work. This document has three parts:

1. **Fixed in this branch** — bugs and hardcoded values found during the review, with tests.
2. **Code & architecture issues still open** — they need a design decision or a larger change.
3. **Functional gaps vs. real-world use** — what an electrician or builder will look for and not find.

The prioritised backlog built from parts 2 and 3 is in [`ROADMAP.md`](../ROADMAP.md).

---

## 1. Fixed in this branch

All of these were verified with unit tests (backend 382 → 392 passing, frontend 56 passing) and,
where it mattered, by running the real API against PostgreSQL 16 and the built frontend in
Chromium.

### Bugs

| # | Problem | Real-world impact | Fix |
|---|---|---|---|
| 1 | Quote numbering counted only non-deleted quotes. After a draft was deleted, the next quote got a number that was already taken, and the retry counted the same value again. | **After any draft is deleted, every new quote fails with a 500 error** until the year ends. Reproduced on the live API. | Numbering counts soft-deleted rows too (`DocumentNumberExtensions.NextQuoteNumberAsync/NextInvoiceNumberAsync`). |
| 2 | Cancelling an invoice left its quote as `Invoiced`, but creating an invoice requires `Accepted`. | You can't reissue a corrected invoice after cancelling a wrong one. | Cancelling puts the source quote back to `Accepted`. |
| 3 | `PATCH /quotes/{id}/status` allowed `Accepted → Invoiced` by hand. | A quote could show "Faturado" with no invoice behind it. | Removed. Only "Faturar" can move a quote to that status. |
| 4 | Stripe: every "Pagar agora" click creates a new Checkout session and overwrites `StripeCheckoutSessionId`. The webhook only looked up by that id. | A client who opens checkout twice and pays in the first tab **pays, but the invoice never shows as paid**. | Sessions now carry `client_reference_id = invoiceId`, and the webhook falls back to it. The amount is rounded, not truncated, to cents. |
| 5 | DB columns are `UnitPrice decimal(10,2)` and `Quantity decimal(10,3)`, but the API accepted any precision. | Cable at €0,4575/m was silently saved as €0,46. The saved quote/invoice total differed from the one shown on screen (reproduced: 162,78 € vs 162,79 €). | Migration widens `UnitPrice` to `decimal(12,4)`. Validators reject more decimals than the columns hold. |
| 6 | List and dashboard totals were computed in SQL without per-line rounding. Detail pages and PDFs round per line. | The list showed different cents from the PDF. | SQL projections round per line the same way as `DocumentMath`. |
| 7 | The quote email attached a PDF with `ClientNif: null`. | Emailed quotes left out the client's NIF, but downloaded ones included it. | Uses `quote.Client.Nif`. |
| 8 | Login rate limiter was **one global bucket** (`AddFixedWindowLimiter`), and there was no `UseForwardedHeaders`. | 10 wrong passwords from anyone locked **the whole company** out of login for a minute. Behind the reverse proxy, every user shared one IP anyway. | Per-IP partitioned limiter plus forwarded headers, trusted only from private/loopback networks (configurable). Verified live. The unused `api` limiter was removed. |
| 9 | Registration was open to anyone forever. | Anyone who found a company's install URL could create their own account (and tenant) on that company's server. | Once the first account exists, registration is closed (`App:AllowOpenRegistration`, default `false`). The UI shows a clear "pede um convite" message. |
| 10 | Team-invite email put `ownerUser.FullName` into HTML without encoding. | HTML injection in an outgoing email. | All emails now go through one layout that encodes everything. |
| 11 | Any 403 made the frontend redirect to `/dashboard`. | Every "Apenas o proprietário…" message was swallowed; the user got bounced with no explanation. | 403 is now rejected normally and shown as a toast. Ardalis's "Next error(s) occurred:*" prefix is stripped. |
| 12 | Blank `SMTP_FROM_ADDRESS` becomes `""` (not `null`), so `??` fallbacks never applied. | With the documented compose defaults, emails were sent with an empty From address and bounced. | Blank-aware fallbacks, plus a clear error if no From address can be resolved. |
| 13 | Uploaded logos live in `/app/wwwroot/uploads` with no volume. | Every `docker compose up --build` deleted the company logo. | Named `uploads` volume, and the directory is pre-created and owned by the non-root user in the image. |
| 14 | Invoices never became `Overdue` on their own. | Overdue filters and the dashboard were only correct if someone flipped each invoice by hand. | New daily `InvoiceOverdueJob`. It goes through the audit log. |
| 15 | Hangfire cron ran in UTC. | "08:00" reminders went out at 09:00 Lisbon time in summer. | Jobs are scheduled in `App:TimeZone` (default `Europe/Lisbon`). |

### Clean-code consolidation

- `DocumentMath` (Domain) is the only place that rounds and sums document lines. `Quote`, `Invoice`, DTOs, PDFs and emails all use it. Before, the line-total formula was copy-pasted into 12 handlers.
- `QuoteMappings` / `InvoiceMappings` replace five hand-built `QuoteDto`/`InvoiceDto` constructors. Line order is now consistently by creation.
- `QuoteLineRequestValidator` is shared by Create/Update quote instead of two copies.
- Removed the empty `Class1.cs` scaffolding and the obsolete Hangfire storage overload.

## 2. Code & architecture issues still open

Ordered by risk. None were changed here because each needs a product decision or a breaking migration.

1. **The discount is applied after VAT** (`Total = SubTotal + VAT − Discount`). In Portugal a commercial discount reduces the taxable base, so VAT should be charged on `SubTotal − Discount`. As it stands, the VAT on a discounted invoice is overstated. Changing the formula would silently change the totals of invoices already issued. It needs a versioned rule (for example a flag on new documents) plus a migration plan.
2. **Invoices aren't legally valid Portuguese invoices.** The README already says this. There's no AT certification, ATCUD, QR code or SAF-T. See §3.1. This is the #1 adoption blocker.
3. **Line order depends on `CreatedAt`.** Lines saved in the same millisecond can come back reordered, and electricians care about line order. Add a `Position` column.
4. **Invoice/quote number uniqueness is global, not per tenant** (`IX_Quotes_Number`). This is fine with registration closed. If multi-company installs ever return, make it `(UserId, Number)`.
5. **The portal JWT shares issuer, audience and key with the staff JWT.** It's safe today only because staff handlers resolve a client id to "no user". Give it its own audience/scheme for defence in depth.
6. **The "Owner or Admin" check is repeated in 14 handlers**, and the tenant check (`entity.UserId != ownerId`) in almost every handler. Use a MediatR authorization behaviour or policies, and an EF global query filter per tenant, so a new handler can't forget it.
7. **Business logic in controllers.** `ClientPortalController` queries the DB, issues tokens and sends email directly. Move it to MediatR handlers like the rest.
8. **Dependency hygiene.** The app targets .NET 10 but uses EF Core / JwtBearer / Serilog **8.x**. Versions use floating wildcards (`8.*`, `10.*`, `2025.*`), so builds aren't reproducible. The test project also pulls `EntityFrameworkCore.Relational` 8.0.11 against 8.0.31 (MSB3277 warning). Pin versions (Central Package Management) and upgrade to 10.x together.
9. **Time handling.** `Npgsql.EnableLegacyTimestampBehavior` is on, and `ScheduledAt` is effectively local wall-clock time while everything else is UTC. Move to `timestamptz`, UTC everywhere, and convert at the edges.
10. **No CI.** There's no `.github/workflows`, so the 390+ backend and 56 frontend tests only run if someone remembers. Add build + test + lint on PR.
11. **No backup story.** Each install is a customer's only copy of their invoices. Document or ship a `pg_dump` cron job plus off-site copy.
12. **Frontend styling.** Most elements use `style={{ color: 'var(--color-…)' }}` inline instead of Tailwind theme tokens. It works, but it's verbose and hard to keep consistent. Map the CSS variables into the Tailwind v4 `@theme`.

## 3. Functional gaps vs. how electricians and builders actually work

### 3.1 Must-have for Portugal (legal/fiscal) — P0

| Gap | Why it matters |
|---|---|
| **Certified invoicing** (AT-certified software, ATCUD, QR code, SAF-T PT, communication to AT) | Without it, the "Faturar" flow can't be the company's real invoice, so they must type everything again into Moloni/InvoiceXpress/Vendus/etc. **Recommendation: integrate with a certified provider's API** instead of certifying this software. The quote → invoice flow stays here, and the fiscal document is issued there. |
| VAT breakdown per rate on the invoice (art. 36.º CIVA) | The PDF shows a single "IVA" line. Mixed 6%/23% documents are very common in renovation work. |
| **Reverse charge (autoliquidação — art. 2.º n.º 1 j) CIVA)** with an exemption reason per line | Almost every electrician subcontracting to a builder invoices without VAT under reverse charge. The document needs the legal wording ("IVA – autoliquidação") and an exemption code, and today 0% can't carry a reason. |
| 6% VAT for renovation of housing (Lista I, verba 2.27) with the 20% materials rule | This is the typical rate for residential electrical renovation. It needs a helper to split labour/materials. |
| IRS withholding (retenção na fonte) | Sole-trader electricians (category B) invoicing companies must show withholding. |
| **Credit notes** (nota de crédito) and **receipts** (recibo) | An issued invoice can't legally be "cancelled", only corrected with a credit note. Payments need receipts. Partial payments aren't supported at all today. |
| Client address and site address on documents | Quote/invoice PDFs show name, NIF, email and phone, but no address. |
| Company licence numbers on documents (alvará/certificado IMPIC for builders; DGEG technician registration for electricians) | Construction contracts and quotes are expected to show them. |

### 3.2 Electrician / maintenance field work — P1

| Gap | Today |
|---|---|
| **Photos from the phone camera** | Photo fields are text inputs for a URL (`https://exemplo.com/foto.jpg`). Nobody on a site has a URL. Upload/storage exists for logos only. |
| **Intervention report (folha de obra) PDF with the client's signature on completion** | Signatures exist only on quotes. `Intervention.ReportPdfUrl` exists in the domain but nothing generates it. |
| **Electrical test records** per RTIEBT: insulation resistance, earth electrode resistance, RCD trip current/time, continuity, loop impedance, polarity | These are core deliverables for new/altered installations and inspections. There's also no **Termo de Responsabilidade / Ficha Eletrotécnica / CERTIEL inspection** workflow. |
| **Billing a service call without a quote** | Invoices can only be created from an accepted quote. Most breakdown calls ("avarias") are invoiced directly from hours + materials used. The intervention's `Materials` already exist but can't become an invoice. |
| **Time tracking** (start/stop per technician, labour rate/h, travel charge — deslocação) | None. Profitability reports count materials only, and revenue is counted once per intervention, so it's double-counted when a quote has several interventions. |
| **Materials/services catalogue** with cost price, sale price, unit (un, m, m², h) and margin; import supplier price lists | Every quote line is typed by hand, and lines have no unit of measure. |
| **Schedule / dispatch view** (calendar per technician, drag to assign, today's route) | There's a list view only. |
| **Mobile/offline** (PWA, works in basements with no signal, syncs later) | Responsive web only. |
| **Maintenance contracts** (avenças) with recurring visits and recurring invoices | `Equipment.NextMaintenance` is a single date that isn't advanced automatically after a visit. There are no contracts or periodicity. |
| Electrical installation data on equipment/site: CPE code, contracted power (kVA), supply type, installation category | Equipment is generic (type/brand/model/serial). |
| Priority / emergency call-outs, SLA | None. |

### 3.3 Construction companies (obras) — P2

| Gap | Today |
|---|---|
| **Projects / sites (obras)** grouping quotes, interventions, invoices, costs, with a site address separate from the client's billing address | Everything hangs directly off a client. |
| **Structured quotes**: chapters (capítulos), bill of quantities (mapa de quantidades / medições), optional items, **versions/revisions** | Flat list of lines. Editing is allowed only in Draft, and there's no revision history once sent. |
| **Progress billing** (autos de medição) — invoice X% of each chapter as work advances | One invoice per quote, 100% at once. |
| **Retention guarantee** (retenção de garantia, typically 5–10%) and **advance payments** (adiantamentos) | None. |
| **Change orders** (trabalhos a mais / a menos) linked to the original quote | None. |
| Budget vs. actual per project (materials, hours, subcontractors) | Only a materials-vs-quoted report. |
| Suppliers, purchase orders, subcontractors | None. |
| Site diary (livro de obra), H&S documents, document storage per project | None. |

### 3.4 Smaller but noticeable

- Quote acceptance by the client online (link + signature from their phone). Today the technician signs on their own device.
- Quote follow-up reminders ("orçamento enviado há 7 dias sem resposta").
- Maintenance alerts go to the owner only, never to the client, and only by email.
- Duplicate a quote / quote templates for recurring jobs (e.g. "substituição de quadro elétrico T2").
- Export to Excel/CSV for the accountant.
- Madeira/Açores VAT rates (22/12/5 and 16/9/4).

## How to use this

- **Merge this branch first.** It's all bug fixes and consolidation, with no behaviour change beyond the fixes listed above. It includes one additive migration (`WidenLineUnitPricePrecision`).
- Then decide on **§2.1 (discount before VAT)** and **§3.1 (certified-invoicing integration)**. Those two decide whether a Portuguese company can use this for real billing.
- The next highest-value field features are camera photos, the signed intervention report, and invoicing from interventions (§3.2). They reuse entities that already exist.
